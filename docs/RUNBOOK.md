# 运行手册

## 日常检查

- Java 就绪探针：`GET /actuator/health/readiness`
- Java 指标：`GET /actuator/prometheus`
- AI 健康：`GET /health`
- AI 指标：`GET /metrics`
- PostgreSQL、Redis、RabbitMQ 容器健康状态

Prometheus 使用 `infra/observability/prometheus.yml`。建议告警红线：5 分钟错误率超过 2%、核心 API P95 超过 300ms、AI 首次响应超过 2 秒、支付回调连续失败、数据库连接池使用率超过 80%、磁盘剩余低于 20%。

## 事故处理

1. 冻结发布并记录故障开始时间、版本和受影响功能。
2. 检查健康探针、最近部署、Flyway 版本和外部依赖，不在日志中复制令牌或完整个人信息。
3. 支付或订单异常时优先关闭对应写入口，保留查询和人工客服通道。
4. 应用问题回滚到上一镜像；数据问题先创建快照，再执行经复核的修复脚本。
5. 恢复后核对订单、支付回调幂等记录和审计日志，再逐级恢复流量。

## AI 客服降级

模型或检索不可用时返回固定服务说明和人工转接入口；不得凭空生成订单状态。退款、取消和改价始终要求登录、权限检查与用户确认。

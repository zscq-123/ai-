日期：2026-11-06，12:57:44–12:58:16（Asia/Shanghai）。

共完成 **21 次浏览器实际提问 + 3 项浏览器内接口边界测试**。人工逐条核对结果：**15 项通过、5 项部分通过、4 项未通过**。基础事实问答与本轮安全限制可用；多轮上下文、英文检索、已关联订单语义和异常提示仍需改进。这是一组本地功能抽测，不是模型通用能力评分。

## 范围与方法

- OMS 使用现有本地管理账号，在客服页面真实填写订单号和问题；独立站使用 390 × 844 浏览器窗口，在右下角客服逐条发送问题。
- 本轮使用当前服务配置 DeepSeek / deepseek-flash，含现有意图判断、规则回复和事实校验；没有启用自训 LoRA。
- 联系方式、地址、配送及售后政策与本地 PostgreSQL 的 chat_knowledge 记录核对，评价的是与项目知识的一致性，未核验这些商户政策在现实中的时效性。
- OMS 订单 O2026102518094583000：状态 7（已取消），金额 14.7 SGD。前后均通过同一订单详情接口读取，字段一致。
- 每次提交都核对浏览器实际发送的 message 和 orderNo；原始 HTTP 状态、回复、引用、人工标记及截图均保留。
- 同一应用内连续提问；S01→S02 专门测试历史承接，OMS 关联订单在 O02–O08 保持不变。O03 正确回答依赖每轮重取订单证据，不能当作历史记忆通过。
- 只发送咨询及只读查询。未执行退款、改价、改地址、发货或人工工单提交。匿名聊天会按应用原有逻辑写入本地聊天历史。
- 当前未覆盖真实客户登录后的独立站订单、跨商户账号端到端访问、真实物流/支付/人工排队状态或生产环境。
- 统计仅使用最后一次完整、请求内容校验通过的运行；早期浏览器自动化焦点/输入选择问题的原始记录另存 raw-previous-*，不作为客服失败计分依据。未用这些问题修改模型、提示词或业务代码。

## 主要问题与建议顺序

1. **多轮上下文丢失（S02）**：问完联系方式，再问「请把刚才那条再发一遍」即返回信息不足。当前接入只向 ChatService 传当轮 message/身份，没有传入会话历史。应增加受来源和身份约束的会话上下文，订单证据仍每轮重新鉴权读取。
2. **已知订单状态未用于付款追问（O04）**：订单实际已取消、引用也存在，回答却只说无法确认付款状态并再次索要订单号。需要把订单状态、支付状态和退款到账状态分别表达；已取消不等于已退款，但应明确呈现已取消事实。
3. **英文联系咨询无检索结果（S07）**：中文问题可答，英文问题返回中文兜底且无引用。当前 ChatController 只用规则 keywords 做子串匹配；数据库联系规则仅有中文关键词。应补全多语言检索和答复语言一致性。
4. **不存在订单被误报为连接失败（O09）**：HTTP 404 被 SupportView 的统一 catch 文案变成「请检查服务连接」。应按 401/403/404/超时分别给出可操作提示。
5. **普通问好过度兜底（O01）**：用户还未提出具体业务问题就收到信息不足。应有准确的能力介绍和示例问题。
6. **人工与物流提示不贴合实际入口（S10/O06）**：人工转接出现内部工具术语；OMS 物流问题指向「我的订单」并再次索要已关联订单号。应使用本应用真实入口，明确工单申请与真人接通的区别。
7. **实时商品及优惠能力仍未接入（S08/S09）**：没有编造价格、库存或优惠码，但也未完成查询。需先提供可信数据接口，再扩大客服承诺范围。
